# 选品调研

`index.ts` 统一导出模块目录 `MODULE_CATALOG`、只读契约 `RESEARCH_SCHEMA`、输入/输出类型、16 个 `MODULE_MAPPERS` 和数据加载入口。

模块目录依次为：市场背景调查、谷歌趋势、站内竞争情况-关键词、广告难易程度&类目平均转化率预估、市场大盘分析、竞品分析、QA&RV分析、流量位竞品数量、站点广告盈亏、流量位竞争格局、词库联动、合规门槛、垄断性、新品表现、知识产权、利润表。模块编号固定为 1—16。

- `schema.ts` 保存章节、中文列 key 与行标签；renderer 仅遍历 columns，不从数据对象推断列。
- `mappers.ts` 从规范化 `ResearchInput` 映射全部列；每个单元格包含 value/status，可附 note。复合统计中的缺值同样包含状态。
- `load.ts` 是路由结果的边界适配器。销量仅 SIF；销售额仅卖家精灵子体 totalAmount；优惠及历史报价仅 Keepa。未配置不混入演示值。
- `demo/research.ts` 提供独立合成样本和 FakeResearchMcp。页面默认演示，可在设置后切换真实模式。演示模式忽略外部 client，绝不发出请求。

动态结构只有三处：竞品/QA 的 ASIN 列、市场底表打标列及按月展开列、属性维度块。属性名按中文顺序排列，底表始终先固定列、再属性、再按月份升序展开四个度量字段。固定列的 `{期末月}` key 由 UI 展开显示名称。模块 9 契约要求 Top3 转化率三个 ASIN 分列，采用稳定序号 `top3产品转化率（ASIN 1）` 至 `（ASIN 3）`，不把实际 ASIN 当作列 key。

模块 1 按目标节点 BSR 1—100 保留全部候选记录（并列可超 100 行），保留模板指定的逐行父体原值求和口径，并明确它不等于去重市场总量。其余模块汇总父体月销量只计一次；同月有子体序列时不叠加父体字段。不能将父体总量分配给子体性能或新品分类。Listing 份额始终按当月 SIF 有值 ASIN 计数，独立于销量去重。模块 5/13 共用集中度计算，按品牌 CR3 / 卖家 CR10 的销售额口径给出等级。

数据缺口处理：原契约与参考源码没有披露广告轮播页数经验阈值，因此该列 unavailable，口径说明保留待核实原因。真实模式只消费已确认的 SIF 平行销量序列、卖家精灵按月金额字段、规范化 Keepa records；未知 Dinzee 响应不会猜测优惠字段，会给出运营时光机提示。Google Trends、评论聚类、外部渠道、合规/IP 等未接入的证据由规范化输入提供，未提供则保留缺失/不可用状态。没有凭据时可完整检查 16 个模块的演示呈现。

验证：在 extension 运行 `npm test`、`npm run compile`、`npm run build`。快照只含固定契约与合成月份，不含外部数据或设置。
