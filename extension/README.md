# 天机AI选品（Chrome 插件）

“用爆款做爆款”：输入自己的老品 ASIN，把同细分市场的爆款拆成元素，对照出“我还差什么、还能怎么改”，每个方案只改一个变量，打分后生成假设卡，结果写入飞书多维表格团队知识库。设计见 [DESIGN.md](DESIGN.md)。

## 安装与构建

本目录是仓库的 npm workspace。先在**仓库根目录**安装依赖并构建：

```bash
npm ci
npm run build:extension
```

Chrome → `chrome://extensions/` → 开发者模式 → 加载已解压的扩展程序 → 选本仓库的 `extension/.output/chrome-mv3`。安装、Web Demo 及所有工作区命令见 [根 README](../README.md)。

## 设置
1. 在设置页填写自己的卖家精灵 MCP 密钥、OpenAI API Key（或兼容中转）。源码不预填任何凭据或团队应用标识，凭据仅在运行时存入本机浏览器。
2. 飞书团队知识库：
   - 飞书开放平台创建企业自建应用，开通 `bitable:app`（查看、评论、编辑和管理多维表格）权限并发布版本；
   - 新建一个多维表格 → 右上角 … → 添加文档应用 → 把应用加为可编辑；
   - 把多维表格链接粘到设置页，点“连接并建表”，自动建好 细分市场 / 爆款元素 / 标签体系 / 升级假设 四张表。
   - 知识库（wiki）里的多维表格要用“在新窗口打开”后带 `/base/` 的链接。

## 流程
1. 弹窗输入 ASIN（在亚马逊商品页会自动带入）→ 切细分市场：TOP200 去重、AI 判配件和形态、价格区间切割，**人工确认**后继续。
2. 对标爆款（按《竞品爆款反向拆解模板》爆款选取标准）→ 元素卡 → 属性矩阵 → 差评死法（标签体系按市场锁定复用）→ 差距矩阵 → 单变量升级方案 → 七维评分（看短板）→ 假设卡。
3. 自动写入飞书；团队在知识库页或飞书表格里改“状态 / 测试指标 / 测试结论”。同一 ASIN 重新诊断时，同杠杆同标题的卡片会更新而不是重复新建，已填的状态保留。

弹窗里“查看演示”用一套模拟的宠物饮水机数据跑完整流程，不调用任何接口。

## 开发与测试

下列命令在 `extension/` 内执行（先完成根目录的依赖安装）：

```bash
npm run dev       # WXT 开发模式
npm test          # 原有 Vitest 单元测试，无需凭据
npm run compile   # wxt prepare + tsc
npm run build     # 类型检查 + Chrome MV3 构建
```

加载插件后通过弹窗的「查看演示」打开 `report.html?demo=1`。不依赖原机器的 `.claude/launch.json` 或外部源码目录。`DESIGN.md` 是保留的设计草案，包含尚未实现的功能规划。

## 尚未实测
- 真实卖家精灵密钥、OpenAI Key、飞书应用下都没跑过全流程；首次使用可能需要按真实返回调整字段。
- 飞书接口按开放平台文档实现（tenant_access_token、tables、fields、records/search、batch_create、batch_update），未用真实应用验证。
- `competitor_lookup` 没有稳定的父体字段，去重用“同品牌 + 标题前 6 词 + 价差 ≤ 15%”近似。
- FBA 费率是美国站非旺季参考表（`core/score.ts` 的 `FBA_TABLE`），需按当年费率核对。
