# 天机AI选品 · 产品升级方向诊断详细设计（v0.1 草案）

> 本文保留原插件设计草案，包含尚未实现的规划；当前安装方式与功能边界以 [仓库 README](../README.md) 和 [插件 README](README.md) 为准。

> 定位：输入**自己的老品 ASIN**，把同细分市场的爆款拆成元素，对照出“我还差什么、还能怎么改”，每个方案只改一个变量，打分后生成可测试的假设卡，测试结果写回**团队共享知识库**。
> 理念来源：用户提供的两篇文章（爆款=需求地图 / 他无我有他有我优）+ 知无不言约 30 篇选品文章 + 用户自己的《竞品爆款反向拆解模板》《一键生成改款设计方案》。

## 0. 一期范围（已确认）

| 项 | 决定 |
|---|---|
| 形态 | 独立新插件 `product-upgrade-extension/`，不并入 VOC 插件 |
| 主场景 | 诊断自己的老品（新品开发入口放二期） |
| 知识库 | 团队共享（存储方式待定，见 §6） |
| 成本 | 采购价、包装、头程单价手动填；FBA 费、佣金、退货损失由程序估算 |
| 站点 | 美国站 |

技术栈沿用 VOC 插件：WXT + React + TypeScript + vitest；卖家精灵 MCP（`secret-key` 请求头）+ OpenAI。可直接复用 VOC 插件的 `services/sellersprite.ts`、`services/openai.ts`、`core/stats.ts`、商品页解析（`parseListingPage`）、`demo/` 模拟数据模式。

**全局纪律**（来自 AI+MCP 选品系列、差评拆解系列、Dreamer 分享）
1. AI 只打标签、归并同义词、写文案；所有计数、比率、分数由程序算。
2. 每个比率显示“分子来源 / 分母来源 / 样本量”；样本 < 30（分组）或 < 100（评论）只报数、不下结论。
3. AI 处理逐条循环（每批 ≤ 20 条），不一次喂几百条。
4. 输出的是候选池和假设，最后由人拍板；每个关键结论能点开原始证据（评论原话、ASIN、关键词）。

## 1. 主流程（9 步，每步一张结果页签）

```
我的 ASIN
 ├─① 切市场：找到“我真正所在的细分市场”
 ├─② 市场阶段与历史：现在该走什么价位/方向
 ├─③ 需求地图：买家在什么情境下、为了什么买
 ├─④ 对标爆款 + 元素拆解 + 属性矩阵
 ├─⑤ 差评死法诊断（我 + 对标爆款）
 ├─⑥ 差距矩阵：我 vs 元素地图
 ├─⑦ 升级方向生成（单变量）
 ├─⑧ 收敛评分（含总成本、复制门槛、短板视图）
 └─⑨ 假设卡 → 验证 → 结果回写知识库
```

### ① 切市场（AI+MCP 系列、竞卖调研篇、竞品库三步法）
- **取数**：`asin_detail`(我) → `nodeIdPath`（没有就 `competitor_lookup asins=[ASIN]` 反查）→ `competitor_lookup` 精确节点、按销量排序，取 TOP200（size=100 × 2 页）。
- **清洗（程序）**：按父体去重（字段需实测；没有父体字段时按“品牌+标题前 N 词+价格”近似）；记录去重比例。
- **配件识别 + 形态分组（AI 逐条，标题+主图）**：先判是否配件（含 “for XX / XX 支架” 词序无关、with/includes 后不算主体），再从本节点标题高频词里反推形态词表，AI 提议、人工勾选确认。
- **分组质检（程序）**：组内均价是否收敛（最高/最低 ≤ 某倍数）、无组 > 50% 样本、每组 ≥ 30 条，不过就提示人工调整。
- **价格区间切割（程序，竞卖调研篇）**：在我的形态组内按跨度 ≥ 2 美元切区间，每区间算：产品数、销量占比、**单均市占**（对比 1% 基准）、区间垄断度（Top3 占区间销量）、评论占比 vs 销量占比（销量占比高而评论占比一般 = 近期热销新品）。
- **产出**：我的细分市场（形态组 × 价格带）+ 已剔除的 ASIN 清单（人可改）。后续所有步骤都以这个样本为准。

### ② 市场阶段与历史（市场调研篇、趋势品复盘）
- **取数**：`competitor_lookup` 带 `month=yyyyMM` 取近 8 个季度末月快照（约 2 年内可查）；`market_product_demand_trend`（退货率、浏览量）；核心词 `aba_research_trend` 周数据。
- **程序算**：季度均价 / 销量 / 品牌数曲线；TOP 样本上架年份分布（换血周期）；季节性指数；近 1 年新品占比与新品销量是否集中在头部多变体。
- **判定（规则）**：新兴 / 细分 / 融合 / 衰落四阶段 + “高端化 or 低价渗透”方向，每条判定附触发它的数据。

### ③ 需求地图（需求时刻地图、AI 关键词需求洞察、购买者≠使用者）
- **取数**：`traffic_keyword`（我 + 对标爆款各 100 词），`keyword_research` 拓词。
- **AI 打标**：去掉品类词，词根归入 场景/人群/功能/材质/尺寸/颜色/风格/季节；标出“购买者词”（gift for / for mom / caregiver）。
- **程序算**：需求簇 = 同一标签被 ≥ N 个词支持；簇的搜索量、购买量、趋势；我在每个簇里的覆盖（有无排名）。
- **产出**：情境簇表（每簇：代表词、规模、趋势、买家担心什么、我是否覆盖）；购买者/使用者两层需求（若存在分离）。

### ④ 对标爆款 + 元素拆解 + 属性矩阵
- **选对标（用户模板《爆款选取标准》）**：从细分市场里按四类挑：新品快速起量型（≤180 天、评论 ≤100、月销 ≥1000）、稳定增长型、黑马型、老品复苏型；标记**伪爆款**（BSR 飙升但评论增长迟缓）。默认选 5–8 个“可学习、可超越”的。
- **小卖家复制法**：按卖家分组，标出“产品数少、销量稳”的卖家，并把打法归类（装饰礼品型 / 技术生态型 / 问题解决配件型 / 季节型）。
- **七类元素卡（AI 逐个）**：需求、场景、人群、结构、视觉（识主图）、价格规格组合（程序）、反馈（好评保留项 / 差评可改项），外加“可迁移元素”。
- **属性矩阵（程序）**：功能 / 材质 / 尺寸 / 结构 / 场景 / 人群 × 出现频次 × 销量；特性 × 价格带绑定；找“有需求无供给”的空白格。

### ⑤ 差评死法诊断（差评拆解系列、竞品评论五层、电源报告）
- **取数**：`review`，我 + 对标爆款各取 1–3 星（文字评论 ≥100 才分析），附带 4–5 星做正负分歧。
- **固定标签体系**：每个细分市场第一次跑时 AI 提议 10–15 个大类，人工确认后**锁定存入知识库**，之后同市场复用，保证前后可比。
- **程序算**：各标签提及率（多标签）、我 vs 对标并排对比、月度差评率趋势、同一功能“被夸 vs 被骂”比例（一致性）、退货损失估算（类目退货率 × 月销 × 单件损失）。
- **AI 归类**：四种死法（品控寿命 / 服务不兜底 / 卖点没兑现 / 基础体验）；三类改进（便宜结构件 / 需供应链配合 / 改不动靠服务兜）；本品独有 vs 品类共性；人群—场景—任务—痛点；用户旅程阶段（购买前/安装/使用/清洁维护/售后）。
- **其他**：先剔除恶意/空泛差评；每个结论带原话和反例；单列“Listing 承诺了什么 vs 买家体验到什么”。

### ⑥ 差距矩阵（我 vs 元素地图）
四格：**他有我无**（爆款普遍具备我没有）/ **他有我劣**（同元素我的差评率更高）/ **他无我有**（我的独有点，检查主图是否表达）/ **都没有**（全品类共性差评，最大机会）。按七类元素出雷达图。

### ⑦ 升级方向生成（单变量）
- **杠杆库**：加部件、可伸缩、可折叠、改规格/组合、做减法、补被忽略的时段场景、换收费/购买方式、一品多场景/多节日、产业降维、反推重定义、服务兜底、被忽视人群/使用者一方/文化小众场景、横向场景迁移、纵向任务链配件化、品质超越。
- **硬约束（程序检查）**：每个方案只能改一个变量；必须写“保留什么（来自好评元素）+ 改什么 + 对应证据 id”。
- **组合检查**：核心品类 × 场景 × 人群 × 关键属性，最多加 1–2 个细分维度；五条淘汰规则：关键词里从不同现 → 淘汰；无用户收益 → 淘汰；体验冲突 → 暂缓；三秒说不清 → 降级；算不过账 → 淘汰（在 ⑧ 判）。
- **两个标签**：差异化等级（补到及格线 / 真正差异化）；需求层次（功能 / 体验 / 安全感 / 审美 / 身份）。
- **跨类目迁移**：从知识库检索其他市场“已验证有效”的元素作为候选（知识库积累后才生效）。

### ⑧ 收敛评分（六维评分 + 收敛五关 + 三道关）

| 维度 | 程序怎么算 | 默认权重 |
|---|---|---|
| 需求证据 | 对应差评提及率、情境簇搜索量、属性空白格销量 | 25 |
| 竞争与位置 | 目标价格区间单均市占、垄断度、千评链接占比；是否落在最挤段 | 15 |
| 感知价值 / 增加成本 | 预估可提价 ÷ 预估成本增量 | 15 |
| 总成本影响 | 体积重量变化 → FBA 尺寸/重量档位、退货原因是否减少 | 15 |
| 复制门槛 | 五层门槛；纯功能改动默认“7–15 天可复刻”降分；门槛低的品叠加“铺货抓取风险”降分 | 15 |
| 实施风险 | 是否开模、认证、专利提示 | 10 |
| 资源匹配 | 人工勾选：供应链 / 拍摄 / 资金 / 团队擅长打法 | 5 |

- **短板视图**：不只给总分，显示每个方案的最低维度，“短板你扛不扛得住”由人判断；权重和阈值可在设置页改，改后全部重算。
- **总成本计算器**：售价 − 采购 − 包装 − 头程（按体积重）− FBA 配送费（程序内置费率表，按年更新）− 佣金 − 广告（词级 CPA 估算）− 退货损失；显示当前包装在哪一档、离下一档还差多少。

### ⑨ 假设卡 → 验证 → 回写
- **假设卡字段**：目标人群、场景、目的、唯一变量、保留项、差异来源、价格逻辑、成本上限、验证动作、成功标准、止损边界、证据链接。
- **老品验证顺序**：先测卖点（主图 / 五点 / 广告按需求标签分组），有响应再打样、改模；新结构可附概念图（二期接 gpt-image）。
- **回写**：填测试结果（CTR、转化、评价、退货原因），元素标记“已验证有效 / 无效 / 待定”。

## 2. 页面结构
- `popup`：输入 ASIN，或在亚马逊商品页一键带入。
- `report.html`：9 个页签 + 每步的人工确认点（市场边界、形态词表、标签体系、对标选择）。
- `kb.html`：知识库浏览（按元素 / 市场 / 假设状态检索）。
- `options.html`：卖家精灵密钥、OpenAI Key、知识库连接、评分权重。
- 导出：Excel（每步一张 sheet）+ 假设卡 PDF/图片。

## 4. 知识库数据模型（团队共享）
| 表 | 主要字段 |
|---|---|
| markets | 市场 id、节点、形态组、价格带、阶段判定、快照日期 |
| products | ASIN、市场 id、对标类型、七类元素（JSON）、卖家打法类型 |
| elements | 元素名、类型、出现市场、热度、可迁移性、验证状态 |
| tag_schemes | 市场 id、锁定的差评标签体系 |
| hypotheses | 假设卡全部字段、评分明细、状态（待测/测试中/有效/无效） |
| test_results | 假设 id、指标、结论、填写人、日期 |
插件只通过 `services/kb.ts` 读写，底层存储可替换。

## 5. 分期
- **一期 MVP**：①（含价格区间）④ ⑤ ⑥ ⑦ ⑧（总成本简化版）⑨（假设卡 + 回写）+ 知识库读写 + Excel 导出。
- **二期**：② 市场历史全量、③ 需求地图与购买者/使用者、小卖家复制法、跨类目迁移检索、概念图生成、新品开发入口。
